AutoQ 2.0

An automata-based C++ tool for quantum program verification.

AutoQ verifies the partial correctness of quantum programs. You state a precondition and a postcondition as sets of pure quantum states and give the program in OpenQASM. AutoQ represents each set as a tree automaton, carries it through the program gate by gate, and checks that every resulting state lies in the postcondition, up to a nonzero complex factor.

1What AutoQ checks

A Hoare triple {P} C {Q} is a claim about a program C: run it from a state allowed by the precondition P, and if it terminates, it ends in a state allowed by the postcondition Q. This is partial correctness, and AutoQ checks claims of this kind for quantum programs, up to scaling.

In AutoQ, P and Q each describe a set of pure quantum states rather than a single state. AutoQ starts from the whole set ℒ(P), computes how it is transformed immediately after each gate, and hands the result to the next gate. When the program ends, it checks that ℒ(Q) contains the final set C(ℒ(P)), up to scaling:

C(ℒ(P)) ⊆uts ℒ(Q) (2)

That is, for every state |s⟩ ∈ C(ℒ(P)) there is a nonzero complex number c ∈ ℂ∖{0} with c|s⟩ ∈ ℒ(Q). A postcondition can therefore leave out normalization factors such as 1/√2; the worked example below relies on exactly that.

uts is short for up to scaling.

AutoQ works with pure states. Mixed states are not considered.

Sets of states as tree automata

AutoQ represents a set of states with a tree automaton. A state becomes a tree with one level per qubit, and each leaf stores one amplitude: in Figure 1 the leaf 000 stores the amplitude of |000⟩, 001 that of |001⟩, and so on. One automaton accepts many such trees, so it can stand for a whole set of states.

AutoQ 2.0 uses level-synchronized tree automata, in which each transition carries a set of choices. It also reorders qubits according to the precondition, postcondition and loop invariants, to keep the automata it builds small.

The internal representation is described in docs/internal_structure.md, which points to Example 1.1.3 of an NFTA reference for background.

2A worked example

This two-qubit example is adapted from the README. The precondition holds two states, and the program applies three gates. Each step shows the set of states after one more gate, the tree of each state, and the output of autoq ex on the program up to that point.

circuit0.qasm, circuit1.qasm and circuit2.qasm in the steps below are the same file cut after zero, one and two gates.

qb[0] is the leftmost bit of each ket, so x qb[0] maps |00⟩ to |10⟩.

The trees follow Figure 1, with leaves in the order 00, 01, 10, 11. In each step, outlined leaves changed with the last gate and dashed leaves hold 0.

All outputs on this page are copied from real runs of a release build. Times and memory figures vary by machine.

  1. 0 Start from the precondition

    ℒ(P) = {|00⟩, 12|00⟩ + 12|01⟩ + 12|10⟩ + 12|11⟩}

    Two states: the basis state |00⟩ and the equal superposition of all four basis states.

  2. 1 x qb[0];

    {|10⟩, 12|10⟩ + 12|11⟩ + 12|00⟩ + 12|01⟩}

    X flips the left bit, so in every tree the two halves under the root swap. The equal superposition maps onto itself, which is why its tree and its line of output do not change.

  3. 2 x qb[1];

    {|11⟩, 12|11⟩ + 12|10⟩ + 12|01⟩ + 12|00⟩}

    X flips the right bit, so under each node of the next level the two leaves swap.

  4. 3 h qb[1];

    C(ℒ(P)) = {|10⟩/√2 − |11⟩/√2, |10⟩/√2 + |00⟩/√2}

    H on qb[1] mixes each pair of sibling leaves a, b into (a+b)/√2 and (a−b)/√2. This is the final set C(ℒ(P)); AutoQ prints 1/√2 as sqrt2*1/2.

  5. 4 Check against two postconditions

    Postcondition Q1 passes

    The same two states without the 1/√2 factors. They match up to scaling, so the check passes.

    Postcondition Q2 fails

    One sign is flipped. The state |10⟩/√2 + |00⟩/√2 is in C(ℒ(P)), but no nonzero factor turns it into a state of ℒ(Q2).

3Get started

AutoQ builds from source on Linux (Ubuntu or Debian), macOS and WSL2. Four steps take you from a fresh clone to a verified program.

  1. Clone the repository

  2. Install the dependencies

    On Ubuntu and Debian, including under WSL2, the script installs g++, make, cmake, libboost-filesystem-dev, libboost-test-dev and libantlr4-runtime-dev with apt, so run it with sudo. On macOS, run it without sudo: it uses Homebrew to install gcc, make, cmake, boost and antlr4-cpp-runtime.

  3. Build and test

    make compiles AutoQ with optimizations, and make test runs the unit tests. The binary is build/cli/autoq. For a debug build, run make debug instead of make.

  4. Verify a program

    ver is the mode used most often in the AutoQ papers. It takes a precondition, a circuit and a postcondition. Here it checks the README’s example, a Grover’s search benchmark on five qubits.

    Times and memory figures in the outputs on this page come from one machine and will vary on yours.

    The demo folder has more small examples, including Bernstein–Vazirani and a Grover iteration.

Z3 is bundled. To use a system-installed Z3, change option(USE_SYSTEM_Z3 ... OFF) to ON in the top-level CMakeLists.txt before building.

Continuous integration runs twelve jobs: build and test, debug and release, on Ubuntu, macOS and WSL2.

AutoQ prints its verdict as [OK] or [failed]. The exit status is 0 for both, and non-zero only on errors such as a parse error, an unsupported gate or misaligned specifications.

Commands

ex
autoq ex [OPTIONS] pre.hsl circuit.qasm
Execute a quantum circuit with a given precondition.
Option: --loopsum
ver
autoq ver [OPTIONS] pre.hsl circuit.qasm post.hsl
Verify the execution result against a given postcondition.
Options: --loopsum, -l, --latex
eq
autoq eq [OPTIONS] circuit1.qasm circuit2.qasm
Check equivalence of two given quantum circuits.
Option: --loopsum
print
autoq print [OPTIONS] states.hsl
Print the set of quantum states.

--loopsum summarizes loops using symbolic execution. -l, --latex on ver prints the statistics for tables in LaTeX. autoq -v prints the full Git commit hash.

4From circuits to programs

AutoQ 2.0 goes beyond straight-line circuits. It verifies programs that measure, branch and loop, and it accepts symbolic amplitudes in specifications. AutoQ can also check whether two circuits are equivalent.

4.1 Symbolic amplitudes

An amplitude may use names that are not declared in the Constants section. AutoQ treats them as free symbolic variables, which the optional Constraints section can restrict. The precondition below, {x|0⟩ + y|1⟩}, therefore stands for every state of that form, and the postcondition requires each amplitude to come back unchanged.

Applying H twice passes. In the H2BugSym benchmark the second H is replaced by Y, and verification fails.

When the precondition, postcondition or a loop invariant is symbolic, AutoQ builds symbolic automata and solves their constraints with Z3, which is bundled with the repository.

4.2 Measurement, branching and loops

A program can measure a qubit into a classical bit and then branch on it with if and else, or loop on it with while. The if block runs on the states where the outcome is 1, the else block on those where it is 0, and AutoQ joins the two results. Both if (!c) and while (!c) are allowed, and else is optional.

A while loop needs a measurement just before the loop and at the end of its body, plus a loop invariant: a set of states in its own .hsl file, named in a comment on the while line. AutoQ checks that the states reaching the loop lie in the invariant, and that one pass of the body maps the invariant’s continuing states back into it. It then carries on with the states that leave the loop.

Measurement can only be used together with if/else or while, not on its own.

AutoQ does not normalize amplitudes after a measurement. Results stay valid, because every non-normalized state has a unique positive factor that normalizes it.

Paths to loop-invariant files are relative to the circuit file.

Put else { on its own line, not on the line of the closing } of the if block.

More examples: control_mini, and the RUS and GroverWhile benchmarks.

4.3 Loop summarization

A loop for int i in [x:y] { C } runs its body C exactly y − x + 1 times. By default AutoQ applies the body’s gates one iteration after another. With --loopsum on ex or ver, AutoQ applies its loop summarization algorithm, which uses symbolic execution, to the loop’s body.

4.4 Circuit equivalence

autoq eq checks whether two circuits are equal. A CX gate equals a CZ placed between two H gates on the target qubit; reversing control and target gives a different circuit.

eq reads the number of qubits from a qreg declaration, so write both circuits in the OpenQASM 2.0 style shown here.

5Writing specifications

Preconditions, postconditions and loop invariants are all sets of quantum states. Specifications are written in .hsl or .lsta; programs in .qasm.

.hsl

A high-level specification language that extends Dirac notation to describe sets of quantum states. A file has a Constants section (optional), an Extended Dirac section, and a Constraints section (optional), in that order.

The .hsl format
.qasm

OpenQASM 2.0 or 3.0, with very limited syntax: a single quantum register, classical bits used only right before control flow, the fourteen gates above, if/else, while and for.

The supported OpenQASM subset
.lsta

A set of states written directly as a level-synchronized tree automaton. It keeps Constants and Constraints and replaces Extended Dirac with Root States and Transitions.

The .lsta format

Reading an .hsl file

The GHZall/002 benchmark runs a two-qubit circuit, h qubits[0]; cx qubits[0], qubits[1];, on all four basis states at once.

  1. {c1 |ji> : |j|=1, |i|=1} lets j and i range over 1-bit strings, so the precondition holds all four basis states. autoq print pre.hsl lists them.
  2. In |1i'>, i' is the bitwise complement of i.
  3. ∪ joins two sets: here, the states with a plus sign and those with a minus sign.

Pre-, post- and invariant files must place ⊗ at the same qubit boundaries, and their variable kets must line up. Otherwise AutoQ stops with an alignment error, for example There are two *.hsl files not aligned!

Names that are not constants, like x and y in section 4.1, become symbolic variables.
